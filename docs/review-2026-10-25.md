# Efficiency and file-format review, 25 October 2026

The review starts from `d920893626f26da8d685a3a047f0a9c51166f926` and retains
the earlier October efficiency improvements. Its target is unchanged:
per-variant association conditional on covariates and fitted polygenic
covariance. No statistical defaults were changed in this review (the Lanczos stopping rule's
`slq_tol` default changed later, on 26 October). Source snapshots and
measurements are in
[`20261025-format-efficiency-review`](../benchmarks/results/20261025-format-efficiency-review).

## Confirmed findings and changes

1. **Incorrect or rejected input (P1/P2).** HDF5 narrowed values to int8
   before validation, allowing fractional dosages or large integers to
   become valid-looking calls. Validation now precedes conversion. The
   CLI filtered phenotype rows without subsetting supplied covariates;
   those arrays now use the same complete-case mask before appending PCs.
   EIGENSTRAT rejects malformed calls and inconsistent row counts.
   Independent review additionally caught TSV blank-cell shifts under an
   explicit wide `IID` header, PLINK covariate -9 missingness, and PSAM
   preamble comments; regression tests cover each correction.
2. **QC memory growth (P2).** A fixed block of 8,192 variants could create
   gigabytes of temporaries in a large cohort. Blocks now contain at most
   8,388,608 calls, or one variant when that is larger. Summing calls and
   correcting their -1 missing entries avoids a masked genotype copy.
   Packed slicing also stops allocating all genome-wide variant indices
   merely to select one small block.
3. **Unnecessary numerical work (P2).** With common degrees of freedom,
   the smallest permutation p-value is the F tail of the largest statistic;
   the scan now evaluates one tail per permutation. The optional LDpred3
   stage-1 LD builder centers/scales its owned rows in place. Invalid LD
   block sizes now raise rather than allowing a nonadvancing loop.
4. **Format and storage gaps (P2).** The CLI was limited to PLINK 1.
   VCF/BCF, PGEN and explicitly thresholded BGEN input now have bounded
   readers; PLINK phenotypes/covariates and compressed TSV output are
   supported. EIGENSTRAT no longer retains all genotype text beside the
   decoded panel, and HDF5 packed export no longer materializes a whole
   unpacked panel. See the [format contracts](formats.md).
5. **Redundant genotype passes (P2, follow-up).** Normalized
   `GenotypeKinship` now collects its scaling moments during the first
   requested traversal instead of making three passes. Its raw diagonal
   is retained in one sample-length float64 vector, including when the
   standardized-genotype cache is disabled. Ordinary HRATT cross-fitting
   now fits effects without computing a full prediction/residual that the
   subsequent LOCO scoring discarded. Cross-validation, chromosome-refitted
   LOCO and in-sample fits still compute their required predictions.

## Measured effects

Table 1 reports warmed function calls on this Mac, with AC power, Low
Power Mode off, fixed seeds and BLAS environment limits of one thread.
Permutation/LD timings are medians of six alternating paired repetitions;
QC uses five. Returned values were exactly equal in these paired checks.
These are component measurements, not whole-GWAS speedups.

Table 1. Paired runtime and peak traced allocations; allocations exclude preexisting inputs and are not process RSS.

| Operation and workload | Before → after | Speedup | Peak allocation, MiB |
|---|---:|---:|---:|
| Permutations: 600 samples, 3,000 variants, 256 permutations | 134.9 → 19.7 ms | 6.86× | 8.9 → 7.9 |
| Stage-1 LD: 5,000 samples, 1,000 variants, blocks of 200 | 40.1 → 21.5 ms | 1.86× | 39.3 → 27.7 |
| Allele frequencies: 12,000 × 8,192, int8 | 103.7 → 43.9 ms | 2.36× | 187.8 → 8.1 |
| Allele frequencies: same panel, packed | 537.0 → 475.9 ms | 1.13× | 281.5 → 34.1 |

For the storage comparison in Table 2, the same synthetic panel contains
uniform -1/0/1/2 calls. Actual compression depends on allele frequencies,
missingness and LD. Files were warm in the OS cache; three alternating
repetitions were used. All decoded calls agreed exactly. The mmap row
measures metadata parsing and mapping; reading mapped genotype pages is
deferred, so its opening time is not a full-data scan time.

Table 2. Warm-cache loading of the 12,000 × 8,192 panel.

| Representation | Load/open time | Peak traced allocation | Files on disk |
|---|---:|---:|---:|
| BED decoded to int8 | 239 ms | 103.0 MiB | 23.8 MiB including BIM/FAM |
| BED retained packed | 13.6 ms | 25.1 MiB | Same files |
| BED memory-mapped | 13.1 ms | 1.7 MiB | Same files |
| HDF5/LZF decoded to int8 | 961 ms | 101.8 MiB | 71.2 MiB |

BED with memory mapping is the preferred working representation for this
hard-call engine. PGEN and VCF/BCF provide interchange; HDF5 remains useful
for existing files. A new custom array format would add maintenance without
removing the need to read standard genetic formats.

Table 3. Follow-up runtime and peak traced allocations; kinship first-use rows disable standardized-genotype caching.

| Operation and workload | Before → after | Speedup | Peak allocation, MiB |
|---|---:|---:|---:|
| First kinship diagonal: 3,000 × 4,096, int8, float32 | 148.6 → 55.1 ms | 2.70× | 29.3 → 11.9 |

| Same HRATT fit, packed calls | 99.2 → 97.6 ms | 1.02× | 22.6 → 21.3 |

The LMM fit uses the streaming SLQ solver and includes BLUP construction;
HRATT uses HE, five folds and a two-model tuning grid. These are synthetic
workloads with warmed kernels, excluding input construction and imports.
Complete fits include their internal setup. Allocation measurements
include returned outputs, exclude untraced native-library allocations and
are not RSS. HRATT's small timing differences are noisy; the eliminated
pass and roughly 1.34 MiB allocation reduction are the firmer findings.
With kinship caching enabled, first-use speedups were only 1.01–1.12×,
though peak allocations still fell. No population-scale runtime claim is
made from these cases.

Every paired result was bit-identical. Sixteen additional kinship checks
covered weights, variant subsets, missing/constant variants, normalization,
storage and precision. Twelve complete HRATT configurations compared 832
result, internal-effect, diagnostic and RNG-state arrays exactly, including
weighted/binary traits, in-sample controls and REML. An independent review
found no correctness issue in either change.

## Remaining limits

- Fractional-dosage inference is still absent. BGEN conversion discards
  uncertainty explicitly; it must not be described as dosage support.
- BGEN input requires zlib/Zstandard compression. Valid uncompressed
  layout-2 input triggers an upstream libbgen/bgen-reader crash, so the
  adapter rejects it before entering the backend. This restriction does
  not repair the upstream decoder's handling of corrupted compressed data
  ([libbgen decoder](https://github.com/limix/bgen/blob/v4.1.10/src/layout2.c#L59-L74)).
- Exact fitting still has dense quadratic storage and cubic factorization
  costs. New readers do not change that scaling.
- Passing input, numerical-equivalence and performance checks does not
  establish scientific calibration. Earlier weighted-selection effect
  bias, weighted runtime and real-data/convergence limits remain open.

An independent dosage implementation, large-cohort end-to-end timings, or
new calibration evidence could change these conclusions. The existing
research-report PDF predates this review; the current evidence is the
source snapshots, JSON measurements and tests linked here.

## Validation

The follow-up complete suite passed **996 tests, none skipped**, including
slow/external tests, real PGEN/BCF readers, and independently encoded
zlib/Zstandard BGEN fixtures. Six expected scientific/legacy warnings
remain. Python 3.14.6 used NumPy 2.4.6 and SciPy 1.18.0; the optional
reader environment used pandas 2.3.3, pgenlib 0.94.1, pysam 0.24.1,
bgen-reader 4.0.9, cbgen 1.0.6 and zstandard 0.25.0. Optional dependencies
were installed in a temporary directory, leaving the core environment's
packages unchanged. The macOS cbgen build required the installed Xcode
26.4 SDK rather than the mismatched default SDK.

Ruff and whitespace checks passed again after the follow-up. The preceding
format review also passed wheel/source-distribution builds and an isolated
wheel import with exact reader-source comparison. CI's full-extras leg now
installs the format readers so these checks do not silently skip. The
checks establish implementation and format contracts, not calibration.
