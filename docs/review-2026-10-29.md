# Release-readiness review, 29 October 2026

The review starts from `74648190489f34e4f74ab33c22ba549b34ad9363`, which is
both `master` and `origin/master`, at package version `2.0.0.dev9`. Its target
is the first public stable release of the 2.0 series, `2.0.0`. The repository
was already public before this review; nothing here changed that, and nothing
here was pushed.

No statistical default, estimator or numerical path was touched. This release
changes the version string, distribution metadata, citation and provenance
documentation, and stops tracking one unused data file, so the measurements in
the [25 October review](review-2026-10-25.md) and the
[29 October evidence bundle](../benchmarks/results/20261029-report-evidence/README.md)
still describe the released code. The report's own manifest records which
package version each archived benchmark ran with.

## Findings and changes

1. **Personal data in a public repository (P1).** `at_data/call_method_75_info.tsv`
   held 1,307 rows of RegMap accession-collection metadata whose columns
   include `firstname`, `surname`, `site`, `region`, `country`, `latitude` and
   `longitude`: the names of the people who collected each accession, with
   where they collected it. Nothing in the package, its tests, its benchmarks
   or its documentation reads the file; the only matches for its name anywhere
   in the tree were the file itself. It is no longer tracked, is kept on disk
   for local use, and is now ignored. Its analysis-relevant content, the
   coordinates, is available from the panel's own published documentation.
   **Limit:** the file remains in the repository's history and in every
   existing clone. Removing it from history means rewriting all 74 commits and
   force-pushing a public branch, which was judged out of scope for a release
   that changes no code; it remains available as a separate decision.
2. **No way to cite the software (P2).** There was no `CITATION.cff` and no
   reference list, so a user who wanted to cite mixmogam, or the methods it
   implements, had to read a 54-page manuscript. `CITATION.cff` now describes
   the software, and the README carries a table mapping each entry point to the
   paper behind it: EMMAX for `method="exact"`, BOLT-LMM for the `bolt` paths,
   LDAK-KVIK for HRATT's two-step design, REGENIE for its cross-fitting, the
   saddlepoint literature for `trait="binary"`, MLMM for the stepwise path, and
   the data and simulator sources. Every identity was taken from the verified
   bibliography in `report/references.json`, which holds each DOI, PMID and
   lookup URL; none was transcribed by hand.
3. **Bundled third-party data had no provenance or licence statement (P2).**
   `at_data/` shipped 176 MiB of *A. thaliana* data with nothing saying where
   it came from or under what terms, next to an MIT `LICENSE` a reader could
   reasonably mistake for covering it. `at_data/README.md` now records the
   source and DOI of each member, the archive snapshot dates, which code reads
   them, the `at_data_cache/` extraction, and the fact that the MIT licence
   covers the software only. It also states that the panel is TAIR10, which the
   README's assembly guidance already asks users to declare rather than guess.
4. **Distribution metadata incomplete for a public release (P2).** The project
   declared no classifiers and no keywords, so PyPI would have shown no
   audience, topic or supported Python versions, and its URLs omitted
   documentation and changelog links. Both are now declared. Classifiers list
   3.10-3.13, matching what CI verifies; no `License ::` classifier was added,
   because PEP 639 forbids combining one with the `license = "MIT"` expression
   already in use. The distribution author became the entity `mixmogam
   contributors`, matching the manuscript's existing `\author` block; the
   copyright holder stays named in `LICENSE`, which is where that belongs.
5. **The source distribution shipped stale build metadata (P3).** `python -m
   build` in the working tree included `mixmogam.egg-info/`, eight files left by
   the in-tree editable install, whose `PKG-INFO` still recorded the previous
   version. `MANIFEST.in` now prunes it, which removes six of those files;
   setuptools regenerates `SOURCES.txt` there during every sdist build, and
   that one is current rather than stale, so two entries remain. `MANIFEST.in`
   also now includes `examples/`, whose three scripts were previously
   distributed nowhere, and `CITATION.cff`. The related environment defect is
   that `pip show mixmogam` reported `2.0.0.dev9` after the bump, because an
   editable install's recorded metadata does not follow the source; the release
   refreshed it with `pip install -e . --no-deps`.
6. **The README's install line omitted three extras (P3).** It listed
   `fast,formats,plot,test,lint` and then described `bgen`, `hdf5` and
   `dataframe` in the next sentence, so following it verbatim left the
   documented readers uninstalled. It now installs every extra, states that
   only NumPy and SciPy are required, and says plainly that the package is not
   on PyPI.
7. **`LICENSE` claimed a single year (P3).** It read `Copyright (C) 2013`, the
   legacy package's year, on a release whose 2.0 series was written in 2026. It
   now reads 2013-2026; the grant text is unchanged.

## Not changed, and why

- **Repository weight.** The pack is 855.81 MiB over 25,454 objects, with
  40,549 of 40,727 tracked files under `benchmarks/`, and `at_data/at_genotypes.zip`
  is 153.6 MiB on its own. That weight is the evidence discipline the research
  report depends on: its Table 1 cites archives by run id, and the manifests
  hash their inputs, so pruning them would break links a reader can currently
  follow. Left as-is. One consequence is worth recording: GitHub rejects
  pushes containing files above 100 MiB, so that panel, already in history,
  cannot be replaced or re-added by an ordinary push. Any future change to it
  needs Git LFS or an external archive with a hash recorded here.
- **Two disclosed benchmark-driver defects.** `benchmarks/README.md` already
  states that `hratt_efficiency.py` passes `--cache-bytes` under the wrong
  package keyword and does not forward `--loco-folds` to its paired worker, and
  that `kvik_scale.py` observes rather than gates load. Both were confirmed in
  the source: `hratt_efficiency.py` sets `fit_options["cache_bytes"]` at line
  192 where the package keyword is `gram_cache_bytes`, and its paired mode
  rebuilds the worker command with `--cache-bytes` but not `--loco-folds` at
  lines 433-435. They are benchmark-only, have no test coverage, and the
  disclosure is accurate, so this release leaves them. They should be fixed
  before the drivers are advertised as runnable by third parties, since the
  sdist ships them.
- **The private sibling dependency.** `benchmarks/_harness.py` imports
  `phensim`, which is private and not on PyPI, and `benchmarks/README.md` tells
  the reader to `pip install -e ../phensim`. The package and its tests import
  no private sibling, and CI does not run benchmarks, so no public user's test
  run breaks; but a user who installs the sdist and follows the benchmark
  README will hit a missing module. Disclosed here rather than silently
  changed.
- **CI's `external` job.** It installs the private `ldpred3` from
  `master` with a read token to exercise the stage-1 LD seam. The job is gated
  on the token being present, so forks and public pull requests skip it rather
  than fail. Left as-is.
- **CI's Python matrix.** It covers 3.10 and 3.13. This release was verified on
  3.14.6 locally, which is not in the matrix, so the classifiers claim only
  what CI checks.
- **Relative links in the README.** They resolve on GitHub, the package's only
  distribution channel today, but would 404 on a PyPI project page. Converting
  them to absolute GitHub URLs is a pre-upload step, not a pre-release one.

The documentation checker is a throwaway script, not a committed test; the

## Remaining limits

These checks establish that the release is internally consistent, installable
and documented. They do not establish scientific calibration. The limitations
carried by the 25 October review stand unchanged: fractional-dosage inference
is absent, BGEN conversion discards uncertainty explicitly, exact fitting keeps
dense quadratic storage and cubic factorization costs, and the weighted and
binary paths remain experimental, with the weighted-effect and runtime criteria
of their prespecified validation still failing. A green suite and a clean build
are not evidence about type-I error.

Nothing was pushed, tagged remotely or uploaded. The release commit and its
`v2.0.0` tag are local; publishing them, and any PyPI upload, remain separate
decisions. A PyPI upload in particular is irreversible: a version, once
uploaded, can never be re-uploaded or its number reused.
