# Code review, 14 November 2026

The review starts from `f2aa0719` (`v2.0.0`), the commit the
[29 October review](review-2026-10-29.md) released, and covers everything after
it through `7f10a258` (`master` == `origin/master`, package version 2.2.0):
90 commits spanning 2.0.1, 2.0.2.dev1, 2.0.2.dev2, 2.1.0 and 2.2.0. The delta is
large — 65 package/test files, +13,256/−523 lines — and adds the machinery the
2.0 series did not have: HRATT in two saved/streamed steps, model-SNP subsets
(HapMap3 matching and MAF/LD thinning), the kappa_g relatedness correction with
KING-auto kinship, dosage tests, streaming readers and bounded-memory selections.

This review was report-only when written: nothing in the package, tests,
benchmarks or report evidence was changed by the review itself. The only
review writes were this file and its index entry in the README (which itself
touches a manifest-hashed file — see F3). The 14 untracked
`benchmarks/results/` directories are the user's work in progress; they were
read but not touched. **The findings were subsequently addressed — see
"Remediation" below for the code, test, documentation and release changes
that landed afterwards.**

Method: three parallel tracks — (1) statistical core (lead), (2) memory, IO,
streaming and caching, (3) tests, documentation and release consistency — each
reading the delta against the CHANGELOG's claims and probe-verifying every
finding before inclusion. Hypotheses a probe disproves are dropped, not
reported. All probes ran in the `ldpred3-accelerate` environment with BLAS
threads pinned to 1; probe scripts and track reports are listed in the appendix.

**Result: no Critical; 5 Major (F1, F2, F3, F12, F13), 9 Minor (F4–F11, F14),
1 observation.** The statistical core is sound — the step split, KING rewrite,
saddlepoint Newton, REML/SLQ fixes and kappa_g correction all survived
independent probes, including a null-calibration simulation. The Majors are a
silent sample-index misapplication in `gwas_by_group` (F1), an incomplete 2.2.0
release (F2), a stale evidence manifest (F3), a monomorphic-variant NaN in
GLS-gamma (F12), and a cache temp-file race that can mix cohorts (F13).

## Severity scale

- **Critical** — silently wrong numbers under realistic use.
- **Major** — wrong under specific plausible conditions, or reproducibility /
  independence broken.
- **Minor** — robustness, diagnostics, coverage or documentation gaps.
- **Nit** — cosmetic.

## Findings

### Major

#### F1 — `gwas_by_group` reinterprets in-memory relatedness indices per group

`mixmogam/association.py:299-308`. `gwas_by_group` splits `sample_weights` with
the samples but passes every other option — including `relatedness=(i, j, r)` —
to each group's `gwas` unchanged. Sample indices are then relative to each
group's subset, so a pair list in full-panel indices is silently applied to the
wrong samples in every group that does not own it.

Probe (n=300 split 150/150, pair `(0, 10, r=0.5)` intended for group A's `s0`/`s10`):

```
group A: n_pairs=1, source=pairs, kappa=[0.9955, 0.9955]   <- correct
group B: n_pairs=1, source=pairs, kappa=[0.9978, 0.9978]   <- models s150-s160 as relatives
```

Group B's kappa_g correction is computed from a pair that does not exist in its
data. The failure is silent; the direction and size depend on the residuals
(kappa_g < 1 inflates the statistic).

The safe inputs were probed too: cross-split indices raise `ValueError` (out of
range), a full-panel `Relatedness` object raises `ValueError` (n mismatch),
`.kin0`/`.grm.sp` paths drop out-of-group pairs via `align_pairs`, and
`relatedness="auto"` recomputes KING within each group. Only raw `(i, j, r)`
index pairs are misapplied. The `hratt` docstring's claim that "pairs that cross
the split are dropped" holds for file inputs but not for index arrays, and
contradicts `gwas_by_group`'s own "other options are passed to gwas unchanged".

Fix: in `gwas_by_group`, map full-panel pair indices into each group and drop
pairs with either sample outside it (the `align_pairs` behaviour), or refuse
in-memory relatedness with a message telling the user to subset it; align the
two docstrings. A test with a cross-group pair list would pin it.

#### F12 — one monomorphic variant NaNs every GLS-gamma p-value

`mixmogam/_relatedness.py:857` (`gls_gamma`): the per-group denominator factor
is `mean(zpz / lg.zz[cal])` over random calibration variants, with no guard on
`lg.zz == 0`. A monomorphic variant has zz = 0, so if one lands in a group's
calibration draw, that group's gamma is NaN and **every** variant in the group
gets a NaN p-value. The exact denominator is per-variant and unaffected.

Probe (400 × 600 panel, 3 monomorphic variants, one per chromosome;
`relatedness_correction="gls"`, `n_gamma=600` so the draw covers the panel):

```
gls/exact: NaN p per chrom {'1': 2, '2': 1, '3': 0}   <- only the monomorphic sites
gls/gamma: NaN p per chrom {'1': 200, '2': 200, '3': 200}   <- all 600 variants
control (no monomorphic, gamma): NaN p 0/597
RuntimeWarning: invalid value encountered in divide   (_relatedness.py:857)
```

With the default `n_gamma=1000` on a large panel, a modest fraction of
monomorphic sites makes a calibration hit likely (e.g. 0.1% monomorphic →
~63% chance per draw of 1,000). Unfiltered array panels plausibly carry them.
The result is a whole analysis returning NaN under a generic numpy warning —
loud enough to notice, silent enough to misattribute.

Fix: draw calibration variants from `np.flatnonzero(lg.zz > 0)` (or guard the
ratio and use a nan-mean); a test with a monomorphic site in the panel pins it.

#### F13 — persistent caches use fixed temp-file names: concurrent writers crash, and the LD cache can mix cohorts

`mixmogam/_stream.py:359-364` (`open_subset_cache`, keep=True: `path + ".tmp"`,
`path + ".json.tmp"`) and `mixmogam/_ld8.py:484-516` (`LDCache.put`:
`base + "-meta.tmp.npz"`, `base + ".tmp.npy"`, `base + ".tmp.npz"`,
`base + ".json.tmp"`). Both are reachable from the CLI (`--model-snps-cache`,
`stage1_kwargs["ld_cache"]`) and advertised for reuse across traits.

Two fits sharing a cache directory can overlap on the same key. For the LD
cohort cache the key deliberately excludes samples (`ld_split="all"`), so two
traits with different complete-case sample sets have the **same key but
different payloads**. Both writers open the same `.tmp.npy` inode
(`open_memmap` w+ truncates in place) and the same meta tmp; the winner of the
rename race publishes a payload whose blocks were last written by the *other*
cohort, together with whichever cohort's meta happened to be in the shared
meta tmp. `_validate_layout` checks only dtype/size/tiling, so `get()` returns
the mismatched cover without warning, and `reuse_check` then computes
overlap/F_ST against the wrong build cohort. The loser crashes with
FileNotFoundError. For the subset cache the same-key content is identical (the
key hashes the calls), so the outcome is "only" a crash of one writer.

Probe (real `open_subset_cache` / `LDCache.put` in two threads, barriers
forcing the interleaving; reproduced on repeated runs, re-run by the lead):

```
subset: FileNotFoundError ... mixmogam-stage1-61bc....bed.tmp -> ....bed
LD:     same key for different cohorts; payloads differ
        payload: A=False B=True; meta: A=True B=False   <- cohort B's LD, cohort A's meta
        mismatched cache passes layout validation; get() accepts it
```

Single-writer use is unaffected; the mechanism (fixed tmp names + `os.replace`)
is identical across processes, so the thread demonstration generalizes.

Fix: unique temp names per writer (`tempfile.mkstemp(dir=...)` then
`os.replace`), or an advisory lock per key; optionally store a payload digest
in the layout and check it on load.

### Minor

#### F4 — `model_snps_include` regions collide across unrecognized contigs

`mixmogam/_thin.py:354-393` (`resolve_include`) with
`mixmogam/_hm3.py:127-142` (`normalize_chromosome`): every unrecognized contig
normalizes to `-1`, and region matching uses the normalized code, so a region on
one unknown contig matches variants at those positions on *any* unknown contig.

Probe: panel chromosomes `[GL000220, GL000221, 1, chr1]`, all at position 150;
`model_snps_include=["GL000220:100-200"]` selects indices `[0, 1]` — the
`GL000221` variant too. Separately, dotted contig names (`GL000220.1:100-200`)
fail the region regex (`[0-9A-Za-z]+` has no dot) and match nothing; that half
warns ("match no variant"), so it is loud, not silent.

Impact is bounded — extra variants forced into the stage-1 subset change the
predictor slightly; the association tests themselves remain valid — and the
trigger is narrow (dotless unknown contigs plus a region include). Fix: when the
normalized code is `-1`, match the raw contig string; allow dots in the regex's
contig group. `match_hm3` is not affected (it excludes `chrom <= 0` from position
matching), nor is thinning (it groups by raw chromosome).

the PDF changes." The manifest hashes 59 inputs, not just the PDF; input-only

hashed input changes".

#### F6 — CLI `step2 --dosage` wiring has no test

`mixmogam/cli.py:496-519`. `grep -rn -- "--dosage" tests/` finds nothing. The
underlying `Dosages` / `iter_bgen_dosages` / `hratt_step2` paths are tested, but
the CLI-only shell — BGEN-only validation, the `--hard-call-threshold` conflict,

One CLI test with a small BGEN plus the two error cases closes it.

#### F7 — thinning's "bit-identical rows" claim is not directly pinned

`mixmogam/_thin.py:73` (`_ld_standardize`, the new branchless float32 kernel).
The thinning tests check kept-set soundness/completeness against a float64
reference at r2 tolerance 1e-5 and chunk-invariance of the kept set; nothing
compares the standardized rows themselves (`grep _ld_rows|_ld_standardize
tests/*.py` → no matches). A summation-order change that shifts rows by ~1 ulp
without flipping any keep/drop decision on the seeded panels would pass the
suite while falsifying the CHANGELOG 2.1.0 "bit-identical rows" claim. Add a
direct `_ld_rows` test (packed and int8, missing and monomorphic variants)
against a per-sample-branch float32 reference with `assert_array_equal`.

#### F8 — test tolerances are looser than the claimed numerical bounds

`tests/test_steps.py:110` streams weighted/binary/GLS step-2 comparisons at
`rtol=1e-9` while CHANGELOG 2.1.0 claims "within 3e-12 relative";
`tests/test_steps.py:207-208` compares dosage log10 p at `rtol=1e-4, atol=1e-6`
against the claimed "about 1e-5". A regression 33x the claimed bound still
passes CI. The "15 configurations" (split) and "14 configurations" (step-2
bitwise) evidence counts are review-run measurements, not reproducible from the
suite (7 split configurations and 3+2 streamed ones are tested). Tighten the
tolerances to the claimed bounds or record the measured worst case in the test;
archive the configuration sweeps as a slow test if the counts should stand.

#### F11 — classifiers claim Python 3.11/3.12; CI never runs them

`pyproject.toml:24-30` lists 3.10–3.13; the CI test matrix runs 3.10 (oldest
numpy/scipy, test+lint only) and 3.13 (all extras). The build job uses 3.12 but
runs exactly one test from the sdist. A 3.11/3.12-only regression ships under a
supported classifier with no suite coverage. Add a middle-version matrix entry
or drop the untested classifiers.

#### F14 — drop-behind `MADV_DONTNEED` is a no-op on macOS: the resident-memory claim does not hold there

`mixmogam/_stream.py:221` (`Readahead.at` drop-behind), claim in
`mixmogam/_packed.py:320` and the `_stream.py` module docstring: mapped scans
are documented to keep resident memory near one chunk. On macOS (this machine:
27.2.1), `madvise(MADV_DONTNEED)` returns success but does not drop resident
file pages, so every page a repack/stream scan touches stays resident for the
life of the mapping.

Probe (map a 200 MB file, fault every page, advise DONTNEED over the whole
map; re-run by the lead):

```
start (resident, footprint) MiB: (32.8, 19.0)
after faulting all 200 MB:       (232.9, 19.1)
after MADV_DONTNEED whole map:   (232.9, 19.1)   <- unchanged
```

The pages are clean and reclaimable (phys_footprint stays ~19 MiB; no OOM
risk, no value impact), and the allocation buffers themselves are genuinely
chunk-bounded (a ≤64 MiB repack buffer, verified by construction and a scaling
probe: repack RSS grows with the panel only through the never-dropped source
pages, staying well under the full-decode control). But RSS-based monitoring
reports the whole scanned panel on the platform the CHANGELOG benchmarks were
measured on. On Linux, MADV_DONTNEED does zap pages, so the claim likely holds
there (not testable on this machine).

Fix: use `MADV_FREE_REUSABLE` on Darwin, or document that drop-behind is
advisory-only on macOS and resident pages are clean/reclaimable. No value
change either way.

## Independently verified as correct

The cheaper half of the audit, written down. Everything below was checked by
reading the line of source it describes and, where a number is quoted, by
executing a probe (appendix).

### Statistical core

- **The HRATT step split preserves values.** Independently of the suite's own
  tests: `hratt_step1` → `save` → `load` → `hratt_step2` on a fresh `Genotypes`
  object (600 × 900, 1% missing calls, 3 folds) reproduces `hratt` bit-for-bit
  (max |Δp| = 0, max |Δbeta| = 0). The `.npz` format is arrays + JSON, no pickle;
  `load` validates format and version.
- **Dosage statistics.** Integer dosages on a complete panel reproduce the
  hard-call statistics to max relative p difference 1.8e-6 (median 1.6e-8),
  within the CHANGELOG's "about 1e-5"; NaN-missing dosages match hard-call
  missingness to 1.65e-6 (both mean-impute with observed moments). The dosage
  test's kappa and lambda paths are term-for-term the hard-call paths
  (`_dosage_test` vs `_hratt_test`), and binary/weighted/GLS dosages are refused.
- **KING-robust kinship.** Against a simulated pedigree (240 founders, 100
  descendants, 8,000 variants): parent–offspring phi 0.2483 (truth 0.25), full
  sibs 0.2483, half sibs 0.1228 (truth 0.125); all 50 designed pairs detected.
  The blockwise `king_pairs` and the dense `king_relatedness` agree bit-for-bit
  on 2,748 pairs. With 2% missing calls, parent–offspring phi is 0.2484 — no
  deflation, confirming the jointly-called-marker fix. The opposite-homozygote
  identity (SS′ − DD′)/2 and the float32 exactness bound (< 2^24 variants) were
  checked algebraically.
- **The KING-auto noise floor and refit trigger.** On the unrelated founder
  panel (n=240): 82 pre-floor noise pairs, 0 modeled (floor 0.0430), trigger
  evidence False. With relatives: evidence True at cutoff 0.0454 with 120
  related samples. The n-aware cutoff (E[null pairs] ≈ 1 over all n(n−1)/2
  pairs), the 0.0884 cap, the max(0, median) anchor and the 1% sample-fraction
  rule behave as documented.
- **The saddlepoint Newton rewrite.** 300 pooled trials × 2 tail modes and 120
  conditional trials against the old bracket search: max |Δlog10 p| = 1.5e-9 in
  the region the package actually uses. The one larger discrepancy (3.3e-6)
  occurs at a near-zero score (x = −0.0016, p ≈ 0.99993) that the package never
  sends to SPA (tails require chi2 > threshold²; the binomial near-mask keeps
  |x| ≤ 0.05 sd on the bracket search) — and there Newton is *closer* to an
  independent pure-Python CGF + brentq reference than the bracket search
  (4.8e-6 vs 8.2e-6). The tilted-moment algebra of `_cgf12`/`_binomial_cgf12`
  (all three overflow branches) was checked term by term.
- **The closed-form ancestry ratio.** `_ancestry_ratio`'s quadratic expansion
  matches the per-sample sums to max relative difference 4.4e-16, with all three
  branches exercised (127 closed-form, 33 clip-guarded per-sample, 140 rho = 1).
  The clip guard's spread bound is valid for the orthonormal design.
- **The structure test's sample tiling.** Forced tiling at n = 1,500 (monkeypatched
  budget) reproduces the whole-row statistic to 1.1e-14 excess, and exactly with
  a 900-sample unrelated subset; the centering identity
  `cross -= outer(sums, sums)/m` is exact.
- **The REML/SLQ fixes (2.0.2.dev1).** The orthonormal-basis change cancels R
  from log|X′V⁻¹X| − log|X′X| exactly; GLS, CG and scan paths are consistently in
  Q coordinates with effects mapped back through `solve_triangular(R, ·)`.
  Probe: covariate units ×1e8 (condition number ×1e16) leave h2 unchanged to
  1.3e-15 and rescaled betas to 6.9e-18. The centered trace identities
  (`_spectral_traces`) make the identity-bulk case exact regardless of probe
  norms; zero probes stay in the average (dropping them biased the trace);
  probes are projected off both covariates and the deflated eigenspace;
  roundoff-sized modes are excluded from deflation.
- **The spike-and-slab point mass (2.0.2.dev1).** m = bv/(1+av),
  lw = log π − ½ log1p(av) + ½bm is the exact posterior algebra; a zero-scale
  component now contributes its prior weight instead of dividing by zero.
- **kappa_g and c_X.** The trace identity tr(Q′ΦQ) = q + 2Σ r_ij(QQ′)_ij, the
  HE-on-pairs moment fit for s_f, the block-diagonal V⁻¹ with its eigenvalue
  floor, and the kappa guard's floor-with-warning were checked by hand; the
  weighted and binary paths apply kappa to the retrospective variance and the
  saddlepoint's per-group ratio consistently. **Independent null calibration:**
  on a simulated panel of 200 families × 5 (parents + 3 children, family

  removes the family inflation that the structure lambda leaves behind.
  KING-auto detected 1,802 pairs (≈ 9 per family, as designed), kappa_g ≈ 1.29
  uniformly, c_X ≈ 1.002; the strong-structure warning fired and recommended
  `relatedness=` exactly as documented.
- **Cross-fitting machinery.** `_out_of_fold_loco`'s total-minus-own split for
  raw scores and covariate coefficients, `_family_folds`' LPT packing (families

- **The model-SNP machinery.** HapMap3 matching (rsID/position conflict

- **`gwas_by_group`'s statistics** (apart from F1): per-group effects recovered

### Memory, IO, streaming, caching (~230 probe checks + 44 external parity tests)

- **Streaming readers equal whole-file readers.** BED (mmap, packed and
  unpacked), PGEN (hand-encoded format-2 bytes), text/gzip VCF and fake-BGEN
  iterators bit-match the whole-file readers' calls and all metadata at 1-,
  boundary- and single-block chunk sizes, with missing calls, odd sample
  counts (padding bits), unsorted/repeated contigs and phased GTs; dosage
  streams equal p(AB)+2p(BB) with NaN exactly at the missing mask; early
  `.close()` and mid-stream consumer exceptions close the native readers.
- **Mapped selections stay mapped.** Read-only contiguous selections share
  storage; non-contiguous ones copy to a temp file and stay mapped read-only
  with exact values; identity sample selections share the map; permutations
  repack bit-identically at 1 vs 4 threads; `with_missing` and missing-ID
  alignment never write a read-only source; exception paths (forced write
  failure, 4-byte spill budget) leave zero temp files; the no-Numba fallback
  stays on disk; the repack buffer is ≤64 MiB regardless of panel size.
- **Cache identity holds against every attack probed.** Subset cache v2:
  moment-preserving sample permutations, changed calls, changed moments and
  in-place BED edits all get new keys or verified rewrites; `verify=True`
  catches a single flipped byte. Training LD cache: permutations, changed
  covariates, changed source calls and reordering each prevent reuse; the
  whole-cohort approximate reuse keeps its documented diagnostics. Truncated
  payloads raise; format-version mismatches are clean misses; block-size
  validation rejects 0, negatives, bools, floats and strings.
- **Threaded Gram preparation is bit-identical** at 1 vs 4 workers (grams and
  coefficients, hold-out and cross-fit), a whole fit at n_threads 1 vs 4 is
  bitwise in p and beta, and the extra scratch is +12 MiB (claim: ≤2 GiB);
  per-thread scratch keys and the fold-cache assignment were race-reviewed.
  The partial-cache warning fires before preparation with the exact joint
  byte requirement, and uncached blocks are never decoded during preparation.
- **The PCA guard matches reality**: its QC-tile estimate equals the observed
  maximum tile, the working-memory formula (including the retained-metadata

## What could not be verified

- **Scientific calibration.** A green suite and value-preservation probes are
  not evidence about type-I error. The October reviews' limitation stands: the
  weighted and binary paths remain experimental. The November calibration
  numbers quoted in the CHANGELOG and quickstart (KING noise counts at
  n = 20,000, in-model leak ≤ 0.0014 and refit cost 1.3–3.8× at n = 2,000,
  ldpred3 refit null chi-square 1.122 vs 1.033, family-fold QTL 0.66–0.92×,
  rare-binary 1.2–2.3× nominal) are labelled "not archived" and are not in the
  repo or the untracked dirs; they cannot be re-derived from this checkout.
  The labels are honest; the numbers rest on the authors' simulations.
- **Biobank-scale memory behavior.** The probes here are small (≤ 1,500
  samples); the bounded-memory claims at 100k–500k samples rest on the
  archived October/November benchmark runs and the suite's spy tests, not on
  a fresh large-panel run in this review.
- **Remote tags.** `git ls-remote --tags origin` prompted for the SSH key
  passphrase; a remote-only v2.2.0 tag cannot be ruled out from here (F2).
- **The exact CI external pin.** The external suite ran against ldpred3
  `80ba9e4`, three commits past the pin `2da4735c` (see baseline note).
- **A 2.2.0 distribution build.** No 2.2.0 artifact exists to inspect;
  packaging inclusion is verified from unchanged config + the 2.1.0 artifacts.
- **External CI execution.** Workflows were inspected as configuration only.
- **Real bgen_reader / pysam integration.** Neither is installed in the core
  environment; BGEN streaming was verified against a fake reader matching the
  library's documented contract (as the repo's own tests do), and BCF
  streaming could not be exercised at all. The real readers' block shapes and
  masks remain untested here.
- **Linux madvise behavior** (F14 is macOS-specific) and **cross-process**
  cache races (F13 was demonstrated with threads; the fixed-tmp-name mechanism
  is identical across processes but a two-process race was not separately run).
- **Biobank-scale memory.** IO probes used ≤50 MB packed panels plus structural
  checks of the budget formulas; the 180 GB stream-cache scenario was not run.

## What is genuinely excellent — do not break this

- **The value-preservation culture.** Bit-identity is not asserted, it is
  tested: forbidden-copy spies, one-pass streaming spies, an independent KING
  oracle, value-comparing split tests, decode tests at the exact kernel
  threshold (4,095/4,096/4,097 samples). The step split's "changed no value"
  claim survived an independent round-trip probe bit-for-bit. This is the
  discipline that makes a refactor-heavy delta reviewable at all.
- **The warning system.** Nearly every statistical trap this package can fall
  into has a named, quantified warning: structure without PCs under kappa_g,
  relatives missing from a supplied pedigree, the KING floor dropping 2nd/3rd
  degree relatives under structure, predicted subset inflation, rare-binary
  carrier clustering, non-convergence, partial Gram caches with exact byte
  requirements. The messages say what to do instead, and cite simulation
  numbers with honest "unarchived" labels where they are not archived.
- **Attribution honesty.** The October skeptic rounds' corrections held:
  BOLT-style methods are labelled as mixmogam's, HRATT is "inspired by
  LDAK-KVIK" not identified with it, the BOLT gate difference is documented
  with source references, and unsupported claims were removed rather than
  defended.
- **The evidence discipline.** Hashed manifests, archived source snapshots,
  run-id citations in the report — F3 is a lapse in an otherwise rigorous
  system, and the compact bundle's 349/349 hash match shows the system works.
- **Defensive step-1 persistence.** No pickles, format/version validation on
  load, per-fit caches, sample selection by ID with loud missing-sample errors.
  The `.npz` round trip is bit-exact.
