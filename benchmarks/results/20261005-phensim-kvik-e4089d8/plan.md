# Matched simulation comparison with reference LDAK-KVIK

Protocol written before inspecting association results, 3 October 2026.
An excluded pilot checks interoperability and resource demands; it may change
the final size, but not the hypotheses or method settings in response to power.

The estimands are the rejection probability of a marker with no direct effect
on a global genetic null, rejection on a reserved null chromosome in a mixed
trait, and detection probability of the ten injected QTL. These are different
quantities. In structured, environmentally confounded data, rejection on a
genetic null measures confounding as well as statistical miscalibration.

## Table 1. Factorial design

| Factor | Planned values |
|---|---|
| Independent genotype/phenotype replicates | 6 per cell, fresh panel in each replicate |
| Diploid samples; markers; chromosomes | 800; 6,000; 6 equal chromosomes |
| Population model | phensim Balding–Nichols, 3 populations, Fst 0 or 0.05 |
| LD | independent markers; 50-marker latent AR(1) blocks, rho 0.8 |
| Base phenotype | global genetic null (h2=0); mixed trait (h2=0.5) |
| Mixed trait | half background, half ten QTL, only on chromosomes 1–5 |
| Environment | none; population labels -1,0,1 with target component 0.2 |
| Analysis cells | unstructured; structured; structured + environment; same confounded trait + 2 PCs |
| Methods | exact LOCO EMMAX; mixmogam bolt-inf; mixmogam kvik; reference LDAK-KVIK |
| Threads | 1 per process; jobs run sequentially |

All genotypes and phenotypes are generated by phensim. No case has simulated
missing calls. Population sizes are random; allele-frequency differences and
within-population LD are measured and saved. The LD model is controlled, not
a reconstruction of human demography. Fst=0 and Fst=0.05 use the same ancestral
frequency seed. The unstructured group labels have no phenotypic contribution.
The two leading standardized-genotype PCs are computed without phenotypes;
exactly the same covariate columns enter every method. An intercept is included.

For each panel, phensim draws the background and QTL from chromosomes 1–5;
chromosome 6 has no direct effects, including no background effects. Ten QTL
occupy distinct LD blocks. Their effects are shared across populations.
The confounded trait is `sqrt(0.2) E + sqrt(0.8) (u+q+e)`, then standardized;
the realized component variances and covariance matrix are retained. Component
targets are not asserted to be realized heritabilities. The mixed-trait null
chromosome shares population structure with causal chromosomes, so its false
positive rate assesses robustness to ancestry correlations, not marginal
independence of phenotype and genotype. Markers tagging causal loci elsewhere
are never silently relabelled false positives.

## Analysis and provenance

Primary calibration summaries: lambda GC from p-equivalent chi-square statistics,
rejection rates at 0.05, 0.01 and 0.001, and rates within quintiles of population
loading. Population loading is the fraction of genotype sum of squares explained
by population membership, not an outcome-derived stratification. Also record MAF
and local LD strata. Power: fraction of the ten causal markers detected at
0.05/m and 5e-8. Report replicate means and Monte Carlo standard errors across
independent panels; do not treat correlated SNPs as independent replicates.
Small simulations cannot establish calibration at 5e-8. Method differences use
paired replicates. Failures, missing tests and convergence diagnostics remain
visible; no tuning or failed-replicate replacement based on outcomes.

The phensim PLINK writer counts BIM A2; both analysis readers count A1. Decode
the actual BED bytes independently and assert exact equality to the simulated
A2 calls; assert mixmogam reads 2-G. Verify LDAK allele frequencies, marker IDs,
sample counts and allele labels. Both programs then read the same BED, BIM, FAM,
phenotype and PC files. All methods use LOCO and their documented defaults;
only seeds, thread count and shared covariates are specified. This compares
implementations as supplied, not identical priors or hyperparameter searches.

Time each method in an isolated process including startup, input loading, model
fitting and scanning. Reference time sums steps 1 and 2, and its peak RSS is the
larger stage peak. Measure process RSS with the operating system, not Python
allocation tracing. Common simulation/export/PC construction is outside method
timings and is recorded separately. Code caches may already be warm. Run on AC
with Low Power Mode off. These are laptop workloads, not biobank scaling claims.

Archive raw p-values, complete inputs, commands, logs, status, seeds, truth,
environment, executable hash, source revision and dirty source snapshots.
Aggregate only after execution finishes; pilot results are excluded explicitly.

Reference command specification verified against
[LDAK-KVIK options](https://www.ldak-kvik.com/docs/options) and
[input documentation](https://www.ldak-kvik.com/docs/input).
The official [LDAK repository](https://github.com/dougspeed/LDAK) supplies the
executable; its filename and SHA256, rather than the generic `Version 6` banner
alone, identify the build.
